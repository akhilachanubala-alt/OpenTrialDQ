# Publication Plan for OpenTrialDQ

## Goal

Publish OpenTrialDQ in places that create a public, traceable technical footprint and can support future recognition.

## Recommended Sequence

### 1. GitHub Release

Create a GitHub Release from tag `v0.1.0`.

Use this title:

```text
OpenTrialDQ v0.1.0 - Initial Public Scaffold
```

Use this description:

```text
OpenTrialDQ v0.1.0 introduces a PySpark-based data quality toolkit for public ClinicalTrials.gov datasets. It includes configurable validation rules, ClinicalTrials.gov API response flattening, failed-record outputs, audit summaries, tests, documentation, citation metadata, and a plain-English use case.
```

Attach or link:

```text
docs/release_notes_v0.1.0.md
```

### 2. LinkedIn Launch Post

Publish `publication/linkedin_launch_post.md` as a LinkedIn post.

Purpose:

- immediate professional visibility,
- feedback from data engineers and life sciences contacts,
- early engagement metrics,
- profile-building evidence.

### 3. Hashnode or Medium Article

Published on Hashnode: https://lifesciencesdataengineering.hashnode.dev/designing-reusable-data-quality-checks-for-public-clinical-trial-data-with-pyspark

Recommended title:

```text
Designing Reusable Data Quality Checks for Public Clinical Trial Data with PySpark
```

Use GitHub as the main project link.

### 4. DEV Community Cross-Post

Cross-post a slightly shorter, code-oriented version to DEV Community.

Focus on:

- PySpark,
- open-source project structure,
- rule configuration,
- tests,
- ClinicalTrials.gov API.

### 5. Reviewed Technical Outlets

After the first article and repo receive more polish, submit an adapted version to:

- DZone,
- HackerNoon,
- Towards Data Science,
- Towards AI if future AI/ML content is added.

These may require editorial review.

## What To Track After Publishing

- GitHub stars, forks, issues, traffic, and clones.
- LinkedIn impressions, reactions, comments, reposts, and profile visits.
- Article views and reads.
- External comments and feedback.
- Any links from other websites or repositories.
- Future citations or DOI references.

## Suggested Publishing Order

1. Create GitHub Release.
2. Add GitHub topics.
3. Publish LinkedIn launch post.
4. Publish Hashnode article. DONE.
5. Share article link on LinkedIn as a follow-up post.
6. Invite feedback through GitHub issues.
7. Submit to DZone or HackerNoon after one more project improvement.
