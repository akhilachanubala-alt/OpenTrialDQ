# OpenTrialDQ Publishing Checklist

## 1. GitHub Release

Open:

```text
https://github.com/akhilachanubala-alt/OpenTrialDQ/releases/new?tag=v0.1.0
```

Use:

- Tag: `v0.1.0`
- Title: `OpenTrialDQ v0.1.0 - Initial Public Scaffold`
- Body: use `publication/github_release_v0.1.0.md`

Then click `Publish release`.

## 2. GitHub Topics

On the repository homepage, edit the `About` section and add:

```text
pyspark
clinical-trials
data-quality
life-sciences
healthcare-data
clinicaltrials-gov
data-engineering
open-source
etl
spark
```

Repository description:

```text
PySpark toolkit for validating public ClinicalTrials.gov datasets with configurable data quality rules.
```

## 3. LinkedIn Launch Post

Use:

```text
publication/linkedin_launch_post.md
```

Post with the GitHub repo link:

```text
https://github.com/akhilachanubala-alt/OpenTrialDQ
```

Save screenshots of impressions, reactions, comments, reposts, and profile views.

## 4. Hashnode or Medium Article

Use:

```text
publication/article_publish_ready.md
```

Suggested title:

```text
Designing Reusable Data Quality Checks for Public Clinical Trial Data with PySpark
```

Canonical project link:

```text
https://github.com/akhilachanubala-alt/OpenTrialDQ
```

## 5. DEV Community Cross-Post

Cross-post a shorter technical version after the first article is live.

## 6. Reviewed Publication Submission

After one more project improvement, submit to one of:

- DZone
- HackerNoon
- Towards Data Science

## 7. Evidence Tracking

After publishing, track:

- GitHub stars, forks, issues, releases, traffic, and clones.
- LinkedIn impressions, comments, reposts, and profile views.
- Article views, reads, comments, and external links.
- Screenshots every two weeks during active promotion.
