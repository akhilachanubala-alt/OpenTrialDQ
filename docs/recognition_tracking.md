# Recognition and Usage Tracking

This document explains how to track whether people are reading, using, or engaging with OpenTrialDQ.

## Why This Matters

Open-source work becomes more useful as people discover it, use it, reference it, and give feedback. For a technical profile, these signals can help show public contribution and external engagement over time.

## GitHub Signals To Track

Track these metrics from the GitHub repository page:

- Stars: people bookmarking or endorsing the project.
- Forks: people copying the project to build on it.
- Watchers: people following updates.
- Issues: questions, bug reports, feature requests, or dataset suggestions.
- Pull requests: external contributions.
- Releases: versioned project milestones.
- Referring sites: where visitors are coming from.
- Clones and unique cloners: whether people are downloading the repository.
- Views and unique visitors: whether people are reading repository pages.

## Where To Find GitHub Traffic

1. Open the repository on GitHub.
2. Click `Insights`.
3. Click `Traffic`.
4. Record views, unique visitors, clones, unique cloners, and referring sites.

GitHub traffic history is limited, so take screenshots regularly.

## Suggested Tracking Schedule

Track metrics every two weeks during active publishing periods and monthly after that.

Create a simple log with:

| Date | Stars | Forks | Watchers | Open Issues | Closed Issues | Views | Unique Visitors | Clones | Notes |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| YYYY-MM-DD | 0 | 0 | 0 | 0 | 0 | 0 | 0 | 0 | Initial baseline |

## Article Signals To Track

When articles are published, track:

- LinkedIn impressions, reactions, comments, reposts, and profile views.
- Hashnode views, reactions, comments, and newsletter subscribers.
- Medium views, reads, claps, responses, and followers.
- DEV Community views, reactions, comments, and bookmarks.
- Acceptance or publication in reviewed outlets such as DZone, HackerNoon, Towards Data Science, or Towards AI.

## Citation Signals To Build Later

OpenTrialDQ already includes `CITATION.cff`. After the project reaches a stable release, create a GitHub release and connect the repository to Zenodo to generate a DOI.

Useful citation evidence can include:

- Zenodo DOI.
- GitHub release page.
- Citations from other repositories, articles, talks, or papers.
- External mentions or links.
- Recommendation letters referencing the public project.

## Evidence Folder Recommendation

Keep an offline folder for screenshots and records:

```text
OpenTrialDQ_Evidence/
  github_traffic/
  github_releases/
  article_metrics/
  linkedin_posts/
  external_mentions/
  recommendation_support/
```

## Important Caution

Do not inflate metrics or buy engagement. Recognition is strongest when it is organic, traceable, and connected to genuine technical usefulness.
